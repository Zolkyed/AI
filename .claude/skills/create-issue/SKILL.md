# Create Issue

1. Inspect the repository, issue templates, existing issues, and relevant history for context and duplicates.
2. Draft a concise title and body covering the goal, scope, acceptance criteria, dependencies, and verification.
3. Use existing labels, milestones, and issue relationships only when clearly supported.
4. Show the complete final draft, ask for confirmation, and stop.
5. Run `gh issue create` only after explicit confirmation. Create exactly one issue and return its URL.

Do not modify repository files or create additional GitHub resources.
